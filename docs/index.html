How it worksSelf-hostSource

The only place your passwords are ever in plaintext is your own device.

Plaintext is an open-source password manager that you host yourself. Your vault is encrypted on your phone and computer with your password and a Secret Key that never leaves them, so the server, and anyone who breaks into it, only ever holds ciphertext.

Read the design Browse the source

Plaintext is in early development. The encryption core and the server work and are tested today, and the apps for iPhone, Mac, Android and the browser extensions are being built next.

Built for a server you don't trust

Most password managers protect your vault from outsiders but trust their own server. Plaintext assumes the server itself may be hostile, which also covers a stolen backup, a curious host and a breach you never hear about.

Two secrets, not one

Your keys come from your password combined with a 128-bit Secret Key that is created on your first device and kept in its keychain. A stolen database can't be cracked by guessing passwords, because the Secret Key was never in it.

Nothing for the server to weaken

The salt and the Argon2id settings are fixed by the app itself, so a malicious server has no way to talk your devices into weaker encryption. The server doesn't even store your email.

Each item sealed as a whole

Every login is encrypted as one XChaCha20-Poly1305 blob that is bound to its own id, so fields and items can't be swapped around or quietly edited by the server.

Tampering gets noticed

Each vault carries an encrypted index of every item. Your devices refuse a server that drops an item, adds one, or serves an older copy of a vault they have already seen.

How your keys fit together

The design follows what the 2026 ETH Zurich study of cloud password managers found broken elsewhere, and DESIGN.md walks through every attack it describes and what Plaintext does about it.

# on your device only
password + Secret Key
  └─► Argon2id + HKDF
        ├─► unlock key ─► account key ─► vault keys ─► items
        └─► login key (the server keeps only its public half)

# on the server
a public login key, sealed keys, sealed items
and one counter per vault

Run your own server

The server is one small Rust binary on SQLite that stores sealed blobs and checks who may read them. It needs no other services, so a small VPS or a box at home is enough.

git clone https://git.borodutch.com/backmeupplz/plaintext
cd plaintext
docker build -t plaintext .
docker run -d -v plaintext:/data -p 8080:8080 plaintext

The first account signs up freely and claims the server; set PLAINTEXT_INVITE to let family or teammates join with an invite code, and put the server behind HTTPS.

Where it's going

Every app is native and shares one Rust core for all of its cryptography, so there is exactly one implementation to audit.

iPhone and iPadA SwiftUI app with AutoFill and passkeys, unlocked with Face ID through the Keychain.
Mac and SafariA native app that carries the Safari extension and unlocks with Touch ID.
AndroidA Compose app with the system Autofill service and passkeys, unlocked through the Android Keystore.
Chrome and FirefoxLightweight extensions that unlock through your operating system's keychain on Windows, macOS and Linux.
