Go ahead, store your passwords in Plaintext.

Every security guide tells you never to store passwords in plain text, and this is the one exception. Plaintext is an open-source password manager that you host yourself. Your vault is encrypted on your phone and computer with your password and a Secret Key that never leaves them, so the server, and anyone who breaks into it, only ever holds ciphertext.

Plaintext is in early development. The encryption core, the server, the command line and the MCP server for AI agents work and are tested today, and the apps for iPhone, Mac, Android and the browser extensions are being built next.

Built for a server you don't trust

Most password managers protect your vault from outsiders but trust their own server. Plaintext assumes the server itself may be hostile, which also covers a stolen backup, a curious host and a breach you never hear about.

Two secrets, not one

Your keys come from your password combined with a 128-bit Secret Key that is created on your first device and kept in its keychain. A stolen database can't be cracked by guessing passwords, because the Secret Key was never in it.

Nothing for the server to weaken

The salt and the Argon2id settings are fixed by the app itself, so a malicious server has no way to talk your devices into weaker encryption. The server doesn't even store your email.

Each item sealed as a whole

Every login is encrypted as one XChaCha20-Poly1305 blob that is bound to its own id, so fields and items can't be swapped around or quietly edited by the server.

Tampering gets noticed

Each vault carries an encrypted index of every item. Your devices refuse a server that drops an item, adds one, or serves an older copy of a vault they have already seen.

How your keys fit together

The design follows what the 2026 ETH Zurich study of cloud password managers found broken elsewhere, and DESIGN.md walks through every attack it describes and what Plaintext does about it.

# on your device only
password + Secret Key
  └─► Argon2id + HKDF
        ├─► unlock key ─► account key ─► vault keys ─► items
        └─► login key (the server keeps only its public half)

# on the server
a public login key, sealed keys, sealed items
and one counter per vault

Your vault in the terminal

The plaintext command line keeps your Secret Key and unlocked session in your operating system's keychain. Unlocking lasts 12 hours and, on macOS and Linux, only in the terminal you unlocked in, the way sudo does, so scripts and AI tools use agent keys of their own instead. The installer works on macOS and Linux and checks the download against the release's checksums before it unpacks anything, and Homebrew works too.

curl -fsSL https://getplaintext.org/install | sh
# or
brew install backmeupplz/tap/plaintext

Windows builds and the server binaries are on the releases page. Once the command line is installed, you can create your account on your server, add logins with generated passwords, share a vault with your family and bring everything over from 1Password or Bitwarden.

# CODE is the invite an admin sent you, or your setup code on a new server
plaintext signup --server https://vault.example.com --username alice --invite CODE
plaintext add GitHub --username alice --generate --url https://github.com
plaintext get github
plaintext vault create Family && plaintext vault share Family bob --role writer
plaintext import 1pux ~/Downloads/export.1pux   # also bitwarden and csv

Secrets for AI agents, without handing them over

An agent gets its own account that you own, which can reach only the vaults you share with it and loses a vault when that share expires. It uses a secret by running a command with that secret injected, so the value stays out of prompts and shell history, and every read shows up in the vault's audit log. A model that runs commands can still print whatever it injects, though, so give each agent only the vaults it needs.

# on your computer, which prints a ptk_… key once
plaintext agent create deploy-bot --vault Infra --role reader --expires 30d

# on the agent's machine
export PLAINTEXT_SERVER=https://vault.example.com PLAINTEXT_AGENT_KEY=ptk_…
DATABASE_URL="pt://Infra/Prod DB/password" plaintext run -- ./migrate

For coding agents and chat apps, plaintext mcp is a Model Context Protocol server. The model can search items and read their non-secret fields, run commands with secrets injected and scrubbed from the output, save new logins with generated passwords and ask you for more access, and it doesn't get secret values back unless you set PLAINTEXT_MCP_REVEAL=1. That keeps them out of transcripts by accident, but a model that can run commands can still reach anything in the vaults its agent account can read. In Claude Code, one command adds it:

claude mcp add plaintext -e PLAINTEXT_SERVER=https://vault.example.com \
  -e PLAINTEXT_AGENT_KEY=ptk_… -- plaintext mcp

Claude Desktop reads the same entry from claude_desktop_config.json, which Settings › Developer › Edit Config opens for you, and Cursor reads it from ~/.cursor/mcp.json. Desktop apps don't always see your shell's PATH, so if one of them can't find plaintext, put the full path that command -v plaintext prints into command.

{
  "mcpServers": {
    "plaintext": {
      "command": "plaintext",
      "args": ["mcp"],
      "env": {
        "PLAINTEXT_SERVER": "https://vault.example.com",
        "PLAINTEXT_AGENT_KEY": "ptk_…"
      }
    }
  }
}

Run your own server

The server is one small Rust binary on SQLite that stores sealed blobs and checks who may read them. It needs no other services, so a small VPS or a box at home is enough, and the image runs on both amd64 and arm64.

docker run -d --name plaintext -v plaintext:/data -p 127.0.0.1:8080:8080 \
  -e PLAINTEXT_URL=https://vault.example.com \
  -e PLAINTEXT_SETUP_CODE=a-long-random-string \
  ghcr.io/backmeupplz/plaintext-server

The port above only listens on the machine itself, so put an HTTPS proxy in front of it (or drop the 127.0.0.1: if the proxy runs on another machine) and set PLAINTEXT_URL to the address that proxy serves, because the server only accepts logins signed for the address your apps use to reach it. Then create the first account with plaintext signup --invite and your setup code, which must not contain dots because a dotted code reads as an invite. That first signup makes you the server's admin and keeps anyone from claiming it before you. Everyone after that joins with an invite code from an admin, which plaintext user invite makes. If you'd rather skip Docker, each release also has a plaintext-server binary for Linux and macOS that keeps its database wherever PLAINTEXT_DB points.

Where it's going

Every app is native and shares one Rust core for all of its cryptography, so there is exactly one implementation to audit.

iPhone and iPadA SwiftUI app with AutoFill and passkeys, unlocked with Face ID through the Keychain.
Mac and SafariA native app that carries the Safari extension and unlocks with Touch ID.
AndroidA Compose app with the system Autofill service and passkeys, unlocked through the Android Keystore.
Chrome and FirefoxLightweight extensions that unlock through your operating system's keychain on Windows, macOS and Linux.
